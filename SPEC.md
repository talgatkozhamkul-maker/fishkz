# SPEC.md — Техническая спецификация (v0.2, после пересборки)

Дата: июль 2026. Статус: реализовано (пересборка v2 по результатам аудита v0.1
и исследования рынка). Изменения против v0.1 согласовать с заказчиком.

## 1. Суть продукта
**FishKZ — актуальный справочник рыбака Казахстана** (PWA). Позиционирование
по результатам конкурентного анализа: в КЗ нет работающего современного
каталога — есть устаревшие форумы и разрозненные Telegram/Instagram-сообщества.
Выигрышная ниша: структурированный mobile-first каталог водоёмов + «правовой
слой» (правила, запреты, платность) + доска услуг с прямыми контактами.

Три опоры продукта:
1. **Каталог**: 17 областей → водоёмы → карточка, отвечающая на вопросы рыбака:
   какая рыба, когда клюёт, платно ли, чей водоём (свободный/закреплённый),
   как доехать (2ГИС/Google), что есть на месте. Маркер «данные проверены N дней назад».
2. **Виды рыб**: справочник → «где ловить судака» (обратный поиск по каталогу).
3. **Доска услуг**: путёвки, гиды, туры, базы, попутчики, услуги — прямые
   контакты (телефон за кликом, WhatsApp, Telegram, опционально Kaspi-ссылка).

## 2. Роли
- **Гость** — весь каталог, поиск, доска, карточки объявлений.
- **Пользователь** (e-mail-код) — + создание объявлений (до 5/сутки,
  модерация), управление своими объявлениями в профиле.
- **Админ** (is_admin) — модерация pending-объявлений на /admin.

## 3. Стек и архитектура
Next.js 16 (App Router, TS, Tailwind v4) + Supabase (Postgres/Auth/Storage) + Vercel.
Библиотеки (одобрены заказчиком проекта при пересборке): zod, react-markdown +
remark-gfm (безопасный рендер, без raw HTML), lucide-react.

Ключевые решения:
- **Три клиента Supabase**: `static.ts` (anon, без cookies — каталог рендерится
  статически), `server.ts` (cookies — auth-потоки), `client.ts` (браузер).
- **ISR**: каталог — SSG + revalidate 30 мин; админ-действия дополнительно
  дергают revalidatePath. Доска/поиск/профиль — динамические.
- **proxy.ts** (Next 16 переименовал middleware) — матчится ТОЛЬКО на
  /profile, /board/new, /admin.
- **Ошибки БД ≠ 404**: слой src/lib/data.ts бросает исключение при error
  (→ error.tsx), notFound() — только при успешном «не найдено».
- Обложки водоёмов — процедурные SVG (фото в демо нет); схема поддерживает photos[].
- SEO: metadataBase, OG, sitemap.ts, robots.ts, JSON-LD (Place+geo). PWA:
  manifest.ts + иконки (генератор scripts/gen-icons.mjs).
- Security headers (CSP и др.) в next.config.ts.

## 4. Модель данных (все таблицы с RLS)
- **regions**: 17 областей (name, slug, sort_order).
- **water_bodies**: + managed_status ('reserved' свободный / 'assigned'
  закреплённый — нужна путёвка), price_info, season_notes, facilities text[]
  (тэги из фикс. набора), access_notes, verified_at (маркер свежести), photos[].
- **fish_species** и **water_body_fish** (связка N:M) — «что клюёт» и «где ловить».
- **profiles**: id = auth.uid(), без FK на auth.users (позволяет демо-профили);
  создаётся триггером on_auth_user_created; is_admin защищён колоночными
  грантами (клиент может править только display_name, phone).
- **listings**: категории putevka/guide/tour/base/companion/service; контакты
  phone/whatsapp/telegram (валидация zod: телефоны → +7…, telegram → username,
  kaspi_link → только https://[pay.]kaspi.kz); status pending→active (модерация).
  Лимит 5/сутки — триггером БД.
- **pages**: markdown-страницы (rules, about, privacy).
- RLS: публичное чтение active-контента; insert объявления только своё и
  только pending; автор НЕ может сам активировать; админ — через security
  definer функцию is_admin(). Storage bucket listing-photos: 5 МБ,
  jpeg/png/webp, запись только в свою папку.

## 5. Маршруты
`/` — **главная в стиле 2ГИС**: полноэкранная карта (MapLibre GL + бесплатные
векторные тайлы OpenFreeMap/OSM, без ключей) с метками всех водоёмов и
геопозицией пользователя (каскад: GPS браузера → IP через заголовки Vercel
`x-vercel-ip-*` в `/api/geo` → центр РК). Поверх — выдвижная «шторка»
(мобильный: 3 положения, старт с половины экрана; десктоп: левая панель
400px): поиск, мини-карточка выбранного водоёма («Клюёт», «Открыть»,
«Маршрут в 2ГИС»), виды рыб, регионы, свежие объявления. Контент шторки
рендерится на сервере (SEO сохранён), страница статическая (ISR).
Прежнее решение «карты не встраиваем» отменено владельцем в июле 2026;
тайлы самого 2ГИС (MapGL API, нужен ключ) — в BACKLOG.
`/search?q=` (по названию/описанию/виду рыбы), `/regions/[slug]`,
`/water/[slug]`, `/fish`, `/fish/[slug]`, `/board` (+фильтры категория/регион),
`/board/[id]`, `/board/new`*, `/login` (OTP-код + magic-link fallback
`/auth/confirm`), `/profile`*, `/admin`* (модерация), `/pages/[slug]`,
404/error. (* — за авторизацией)

## 6. Оплаты
Без изменений (v0.1 §6): платформа деньги не принимает; kaspi_link — прямая
оплата владельцу объявления. Возле кнопки Kaspi показывается домен ссылки.

## 7. Вне скоупа (BACKLOG.md)
Прогноз клёва, отчёты сообщества, «цена проверена N дней назад» как механика
с подтверждениями, отзывы/рейтинги, чат, push, встроенные карты, казахская
локализация, нативные приложения, приём платежей платформой.

## 8. Операционное
- Миграции: `node --env-file=.env.local scripts/run-migrations.mjs`
  (журнал schema_migrations, повторный запуск безопасен).
- Назначить админа: `node --env-file=.env.local scripts/make-admin.mjs <email>`.
- DATABASE_URL — только локальный секрет, в Vercel НЕ добавлять.
- Настройки Supabase для входа: Site URL = прод-домен; в шаблон письма
  Magic Link добавить {{ .Token }} (код) и ссылку на /auth/confirm.

## 9. Персональные данные
Минимум: e-mail (вход), имя/телефон в объявлении по желанию автора.
`/pages/privacy` опубликована. Серверы Supabase за рубежом — зафиксировано
с заказчиком письменно (v0.1), перенос в РК — этап 2.
