# SPEC.md — Техническая спецификация MVP (v0.1, предварительная)

Дата: июль 2026. Статус: согласована с исполнителем, открытые вопросы к заказчику — в разделе 10.

## 1. Суть продукта
PWA-сервис для рыбаков Казахстана. Пользователь находит регион и водоём, читает
правила и описание, смотрит объявления услуг (путёвки на водоёмы, гиды, туры,
попутчики) и связывается с автором напрямую. Устанавливается на экран телефона
по ссылке, без App Store / Google Play. Язык интерфейса: русский.

## 2. Роли
- **Гость** — просмотр каталога, объявлений, страниц; поиск и фильтры. Без входа.
- **Пользователь** (вход по e-mail-коду) — всё то же + создание и управление
  своими объявлениями, профиль.
- **Админ** (заказчик, флаг is_admin) — модерация объявлений, ведение справочников
  регионов и водоёмов, редактирование инфо-страниц.

## 3. Стек
Next.js (App Router, TypeScript), Tailwind CSS, Supabase (Postgres + Auth email OTP +
Storage), Vercel, PWA (manifest, иконки, офлайн-заглушка).
Карты НЕ встраиваем: у водоёма хранятся координаты, кнопка «Маршрут» открывает
точку в приложении карт (2ГИС / Google Maps) по ссылке с координатами.

## 4. Модель данных (Postgres, все таблицы с RLS)

**regions** — регионы/области
- id, name, slug, sort_order

**water_bodies** — водоёмы
- id, region_id (FK), name, slug, description
- water_type: enum('lake','river','pond','reservoir')
- lat, lng (координаты), photos: text[] (URL из Storage)
- is_paid: bool (платный/бесплатный водоём), rules_text (правила конкретного водоёма)
- contacts (текст, опционально), status: enum('active','hidden')

**listings** — объявления
- id, author_id (FK profiles), category: enum('putevka','guide','tour','companion','service')
  (путёвка / гид / тур / попутчики / услуга водоёма)
- title, description, price (int, тенге, nullable), price_unit (текст: «за день», «за место»…)
- region_id (FK), water_body_id (FK, nullable)
- photos: text[] (до 5 шт), contact_phone, contact_telegram (nullable)
- kaspi_link (nullable — ссылка на оплату Kaspi владельца объявления, см. раздел 6)
- status: enum('pending','active','hidden','archived'), created_at

**profiles** — профили (id = auth.uid)
- display_name, phone (nullable), is_admin: bool, created_at

**pages** — инфо-страницы (правила рыбалки РК, о сервисе, конфиденциальность)
- slug, title, content_md

RLS: чтение публичных данных (status='active') — всем; создание/изменение
объявления — только автору; всё остальное — только админу.
Новое объявление получает status='pending' до одобрения админом.

## 5. Экраны и маршруты
1. `/` — главная: поиск, список регионов, свежие объявления
2. `/regions/[slug]` — водоёмы региона
3. `/water/[slug]` — карточка водоёма: фото, описание, тип, правила, кнопка
   «Маршрут», объявления по этому водоёму
4. `/board` — доска объявлений: фильтры (категория, регион, цена), список
5. `/board/[id]` — карточка объявления: фото, цена, описание, контакты
   (телефон, Telegram/WhatsApp-ссылка), кнопка «Оплатить через Kaspi» (если есть kaspi_link)
6. `/board/new` — создание объявления (только для вошедших): категория, регион,
   водоём (опц.), заголовок, описание, цена, фото до 5 шт, контакты
7. `/login` — вход: e-mail → код подтверждения (Supabase OTP)
8. `/profile` — мои объявления (редактировать/скрыть), выход
9. `/pages/[slug]` — инфо-страницы из таблицы pages
10. `/admin` — модерация (лента pending: одобрить/скрыть), CRUD регионов и
    водоёмов, редактор страниц. Доступ только is_admin.

## 6. Оплаты — решение по умолчанию (СОГЛАСОВАТЬ С ЗАКАЗЧИКОМ)
Платформа в MVP деньги НЕ принимает и НЕ обрабатывает. Владелец объявления может
указать свою Kaspi-ссылку/QR — покупатель платит ему напрямую. Это закрывает
кейс «оплата путёвки», не требует сверки платежей и снимает с платформы
ответственность за чужие деньги. Монетизация самой платформы (продвижение
объявлений и т.п.) — решается после эксперимента, в MVP отсутствует.

## 7. Вне скоупа MVP (не делать)
Нативные приложения и публикация в сторах; приём платежей платформой; чат между
пользователями; отзывы и рейтинги; избранное; push-уведомления; встроенные
карты; бронирование с календарём; казахская локализация; автомодерация;
купля-продажа снастей (категория осознанно исключена заказчиком).

## 8. Нефункциональные требования
- Mobile-first (базовая ширина ~390px), аккуратный десктоп.
- PWA: установка на экран проверяется на iPhone (Safari → «На экран Домой»)
  и Android (Chrome, автопредложение установки).
- Фото: сжатие на клиенте перед загрузкой, лимит 5 шт × 5 МБ, bucket в Supabase Storage.
- Анти-спам: не более 5 объявлений в сутки на пользователя.
- SEO: метатеги, sitemap для водоёмов и объявлений, человекочитаемые slug.
- Скорость: next/image, ленивая загрузка списков.

## 9. Персональные данные
Собираем минимум: e-mail, имя, телефон в объявлении (по желанию автора).
Страница политики конфиденциальности — обязательна (`/pages/privacy`).
Серверы Supabase за рубежом: для этапа MVP зафиксировано с заказчиком письменно,
перенос в РК — задача этапа 2 (вне кода, ответственность владельца проекта).
